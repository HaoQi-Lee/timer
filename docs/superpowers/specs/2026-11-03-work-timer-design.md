# 上班计时器 · 设计说明

日期：2026-11-03

## 一句话

一个常驻桌面的置顶小挂件（Windows / macOS），显示当前时间、上班状态、距下班倒计时、
今日已赚金额与赚钱速度、物品换算提示和今日工时进度。

## 目标与非目标

**目标**
- 一眼看清"现在该干什么、还要干多久、今天赚了多少"。
- 单文件可执行，双击即用，不需要装运行时。
- 业务规则（排班、薪资口径）可测试、可复核。

**非目标（v1 不做）**
- 考勤打卡、请假、加班统计、跨天累计。
- 节假日日历（法定节假日只参与日薪折算，不参与排班）。
- 托盘常驻与开机自启。
- 云同步 / 多设备。

## 技术选型

**Wails v2（Go 后端 + Web 前端）**。

| 备选 | 不选的原因 |
| --- | --- |
| Electron | 安装包 ~150 MB、常驻内存 ~150 MB，对一个小挂件太重；项目已有 go.mod 会闲置 |
| 纯 Go GUI（Fyne/Gio） | 界面观感偏工具型，做不出细腻排版；macOS 端同样依赖 Xcode |
| Python + PySide6 | 需要 Python 环境，打包 ~70 MB；同样闲置 go.mod |

Wails 的关键优势：业务逻辑用 Go 写（可单元测试），界面用 HTML/CSS 做（可做精致），
最终产物是单个可执行文件。**前端不使用任何框架，也不需要 npm 构建**——
Wails 会在服务 HTML 时自动注入 runtime 脚本，`window.go.main.App.*` 直接可用。

## 计算口径

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 日薪 | 年薪 ÷ 261 | 261 = 52 周 × 5 天 − 11 天法定节假日 |
| 午休 | 不计工时、不发工资 | 符合"工时进度"的直觉 |
| 每日工时 | 7 小时（上午 3h + 下午 4h） | 8:30–11:30 + 13:00–17:00 |
| 时薪 | 日薪 ÷ 7 | |
| 分钟薪 | 日薪 ÷ 420 | |
| 今日已赚 | 分钟薪 × 今日已工作分钟数 | 午休时段不增长 |
| 赚回某物 | ⌈物品价格 ÷ 分钟薪⌉ 分钟 | 从**当前时刻**起算，而不是从上班起算 |

排班（默认，可在设置里改）：8:30 上班 / 11:30 午休 / 13:00 下午上班 / 17:00 下班。
状态机：未上班 → 上班中 → 午休中 → 上班中 → 已下班。

## 架构

```
前端 (HTML/CSS/JS)                Go 后端
┌─────────────────────┐          ┌──────────────────────────┐
│ render(snapshot)    │ ◀──tick──│ App.Snapshot()           │
│ 设置表单             │ ──调用──▶ │ App.GetSettings()        │
│ 右键菜单             │          │ App.SaveSettings()       │
│                     │          │ App.SetAlwaysOnTop()     │
└─────────────────────┘          │ App.Quit()               │
                                 └───────────┬──────────────┘
                                             │
                            ┌────────────────┼────────────────┐
                            │                │                │
                      internal/schedule  internal/salary  internal/goods
                            │                │                │
                            └────────────────┼────────────────┘
                                             │
                                     internal/settings
```

**职责边界**：所有业务计算都在 Go 侧完成，前端只做渲染和表单交互。
前端从不自己算钱、算工时，避免两套逻辑漂移。

- `internal/schedule`：排班 → 状态、已工作分钟数、距下班时间。纯函数，无外部依赖。
- `internal/salary`：年薪 → 日薪/时薪/分钟薪；已赚金额；赚回某物需要多少分钟。纯函数。
- `internal/goods`：内置物品清单；按日期做确定性洗牌（同一天顺序固定，跨天才变）。
- `internal/settings`：默认值、合法性修正、JSON 持久化。

### 数据流

1. `OnStartup` 起一个 500 ms 的 ticker，每次计算一份 `Snapshot`（含时间、状态、倒计时、
   工时进度、各档金额、当前轮播到的物品）并通过 Wails 事件 `tick` 推给前端。
2. 前端收到 `tick` 就把快照里的字段填进 DOM。
3. 前端启动时主动调一次 `Snapshot()` 补上第一帧（事件在页面就绪前发出会丢失）。
4. 设置面板保存时调 `SaveSettings`，Go 侧写盘并立即重建排班与物品轮播，下一帧就生效。

### 物品提示的措辞

物品名按"`X` 就赚回来了"这句话读起来顺当来取，例如"理一次发"而不是"一次理发"。
不同状态下文案不同：

- 未上班：`上班后再过 46 分，一件 T恤 就赚回来了`
- 上班中：`再过 22 小时 51 分，一场旅行 就赚回来了`
- 午休中：`午休中，赚钱速度暂停，稍后再算 ☕️`
- 已下班：`今天已经下班啦，明天继续 💪`
- 已经赚够：`一件 T恤 已经赚回来了 🎉`

## 界面

340 × 500 的圆角深色卡片，无边框、半透明、置顶。层次自上而下：

状态胶囊 → 大号时钟 + 日期 → 距下班倒计时 → 工时进度条 → 今日已赚（强调色）→ 物品提示。

强调色随状态变化：上班=绿、午休=琥珀、未上班=蓝灰、已下班=灰。

打开设置面板时窗口放大到 460 × 660（`runtime.WindowSetSize`），关闭后缩回。

## 交互细节

- 顶部标题栏是拖动区（`--wails-draggable: drag`），里面的按钮单独标 `no-drag`。
- 右键弹出自绘菜单（设置 / 切换置顶 / 退出）；在输入框里右键保留系统原生菜单。
- macOS 的原生菜单放在应用菜单里，Windows 上放在"设置"菜单下。
- 窗口位置会被记住；恢复前会校验位置是否还落在屏幕范围内，否则改为居中。

## 错误处理

| 情况 | 处理 |
| --- | --- |
| 配置文件不存在 | 用默认值启动，下次退出时自动写入 |
| 配置文件损坏 | 记一条日志，用默认值启动，不让程序起不来 |
| 配置文件里时间格式非法 | 逐项回退到默认时间（`Normalize`） |
| 年薪为 0 | 各项速率为 0，提示语改为"设置年薪后…" |
| WebView2 运行时缺失（Windows） | Wails 会弹窗提示安装 |

## 测试

`internal/` 下四个包全部有单元测试，覆盖：

- 排班状态机的每个边界（8:29 / 8:30 / 11:30 / 13:00 / 17:00）与工时累计。
- 年薪折算、已赚金额、赚回物品的分钟数取整。
- 洗牌的确定性与不改动原切片。
- 配置的修正、保存与读取往返、文件缺失时返回默认值。

界面本身靠开发期抓图工具 `tools/shot` 人工核对。

## 已知约束

- **Windows 上 `.app` 不适用**：macOS 的 `.app` 包必须用 Wails CLI 打（`./build.sh mac`）。
- **必须带 build tag**：不带 `desktop,production` 编译出来的程序启动即退出且无报错，
  因为 Wails 的 `CreateApp` 在这种构建下返回空。这是 Wails 手工构建最容易踩的坑。
- **节假日不参与排班**：法定节假日只影响日薪折算（261 天），当天仍然按正常班表显示状态。
- **多显示器**：窗口位置以主屏为基准记录，副屏在主屏左侧时允许 x 为负；
  位置完全跑到屏幕外则改为居中。
